# M0-01 核心组环境

## 目标

在阿里云服务器上能够用一条命令启动 `core` 分组，使 MySQL、HDFS、YARN、Hive Metastore、HiveServer2 和作业提交网关全部可用，并且能够用一条命令检查它们的健康状态。

## 前置任务

无。

## 依据的设计文档

- `docs/00-总体架构设计.md` 第 5 节“技术选型与版本基线”。
- `docs/01-环境与部署设计.md` 第 2 节至第 8 节中与 `core` 分组有关的全部内容，以及第 7.1 节至第 7.3 节。

## 实现范围

1. 新增 `deploy/.env.example`，声明 `core` 分组所需的镜像名称、版本号、发行包下载地址和各数据库账号的默认密码。默认密码必须带有“仅用于示例”的注释。
2. 新增 `deploy/images/hadoop-base/`、`deploy/images/hive/` 和 `deploy/images/gateway/` 三个镜像的构建文件。本任务卡中的 `gateway` 镜像只需要包含 Hadoop 与 Hive 的客户端，Spark 与 Flink 的客户端由后续任务卡加入。
3. 新增 `deploy/docker-compose.yml`，定义 `core` 分组的八个服务，每个服务都设置内存上限、时区、健康检查和 `core` 的 profile，端口只绑定到 `127.0.0.1`。
4. 新增 `deploy/conf/` 下 Hadoop 与 Hive 的配置文件。
5. 新增 `deploy/init/` 下的 MySQL 初始化脚本，创建设计文档第 7.1 节列出的全部数据库与账号。
6. 新增 `deploy/scripts/dp-up.sh`、`dp-down.sh` 和 `dp-health.sh`，本任务卡中它们只需要支持 `core` 分组，但是参数形式必须符合设计文档第 8 节，以便后续任务卡扩展。
7. 更新 `deploy/README.md`，说明从一台全新的服务器开始部署 `core` 分组的完整步骤，包括安装 Docker、克隆仓库、准备 `.env` 文件、构建镜像和启动。

## 明确不做的范围

- 不安装和配置 Spark，这属于 M0-02。
- 不创建任何业务表，不向数据库写入任何业务数据。
- 不实现 `realtime`、`scheduler` 和 `governance` 分组。
- 不编写删除数据卷的脚本。

## 验收命令

以下命令的执行环境均为阿里云服务器，工作目录为 `/opt/dataplatform`。

| 序号 | 命令 | 期望输出 |
| --- | --- | --- |
| 1 | `bash deploy/scripts/dp-up.sh core` | 八个服务全部启动，脚本的退出码为 0。 |
| 2 | `bash deploy/scripts/dp-health.sh core` | 逐项输出八个服务的检查结果，全部通过，退出码为 0。 |
| 3 | `docker compose -f deploy/docker-compose.yml exec gateway hdfs dfs -ls /` | 命令成功执行，能够列出根目录。 |
| 4 | `docker compose -f deploy/docker-compose.yml exec gateway yarn node -list` | 输出中有 1 个处于 RUNNING 状态的节点。 |
| 5 | `docker compose -f deploy/docker-compose.yml exec gateway beeline -u jdbc:hive2://hiveserver2:10000 -e "show databases"` | 输出中包含 `default` 数据库。 |
| 6 | `bash deploy/scripts/dp-down.sh core`，然后再次执行第 1 条与第 2 条命令 | 重新启动之后健康检查仍然全部通过，证明 Hive 元数据的初始化不会重复执行。 |
| 7 | `ss -ltnp \| grep -E '3306\|9870\|8088\|10000'` | 全部监听地址都是 `127.0.0.1`。 |
| 8 | `docker stats --no-stream` | 输出八个容器的实际内存占用。 |

## 已知风险与需要反馈的问题

1. 请验证 Hive 3.1.3 与 Hadoop 3.3.6 之间除 Guava 之外是否还存在其他依赖冲突，并且在合并请求中说明处理方式。
2. 请在合并请求中说明所选的 JDK 8 基础镜像、MySQL 的具体修订版本和 MySQL 驱动的版本。
3. 请反馈第 8 条验收命令中各容器的实际内存占用，架构师将据此修订内存上限。
4. 如果服务器无法访问 Docker Hub 或 Apache 官方归档站点，请说明实际采用的镜像地址与下载地址。
