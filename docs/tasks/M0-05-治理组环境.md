# M0-05 治理组环境

## 目标

能够用一条命令启动 `governance` 分组，DataHub 复用本项目已有的 MySQL 与 Kafka，并且可以通过浏览器登录 DataHub。

## 前置任务

M0-03。

## 依据的设计文档

- `docs/01-环境与部署设计.md` 第 4 节至第 6 节中与 `governance` 分组有关的内容，以及第 7.6 节。

## 实现范围

1. 在 `deploy/docker-compose.yml` 中增加 `governance` 分组的服务，以 DataHub 1.7.0 官方发布的编排文件为基础裁剪，去掉其中自带的 MySQL 与 Kafka，改为连接本项目的 `mysql` 与 `kafka`。DataHub 官方编排文件中用于初始化数据库、主题和索引的一次性容器应当保留，并且归入同一个 profile。
2. 在 `deploy/.env.example` 中增加所需的变量，包括 DataHub 的版本号与管理员密码。
3. 扩展 `dp-up.sh`、`dp-down.sh` 和 `dp-health.sh`，使它们支持 `governance` 分组，并且在启动之前检查 `core` 与 `realtime` 分组已经启动。
4. 更新 `deploy/README.md`，说明登录地址与修改默认管理员密码的方法。

## 明确不做的范围

- 不配置任何元数据采集任务，不接入 Spark 与 Flink 的血缘，这些内容属于里程碑 M4。
- 不创建术语表、数据域和标签。
- 不单独部署模式注册中心，除非验证证明内置的模式注册功能不可用。

## 验收命令

以下命令的执行环境均为阿里云服务器，工作目录为 `/opt/dataplatform`，前置条件是 `core` 与 `realtime` 分组已经启动。

| 序号 | 命令 | 期望输出 |
| --- | --- | --- |
| 1 | `bash deploy/scripts/dp-up.sh governance` | 服务全部启动，一次性的初始化容器全部成功退出，脚本的退出码为 0。 |
| 2 | `bash deploy/scripts/dp-health.sh governance` | 检查全部通过，退出码为 0。 |
| 3 | `curl -s http://127.0.0.1:8080/health` | 返回成功状态。 |
| 4 | `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:9002` | 返回 200 或者跳转到登录页面的状态码。 |
| 5 | `docker compose -f deploy/docker-compose.yml exec kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server kafka:9092 --list` | 输出中包含 DataHub 创建的主题。如果所选 Kafka 镜像中脚本的路径不同，请使用实际路径并且在合并请求中说明。 |
| 6 | `bash deploy/scripts/dp-health.sh core && bash deploy/scripts/dp-health.sh realtime && bash deploy/scripts/dp-health.sh scheduler` | 四个分组同时运行时，其余三个分组的健康检查仍然全部通过。 |
| 7 | `docker stats --no-stream` 与 `free -g` | 输出全部容器的实际内存占用和服务器的剩余内存。 |

## 交付物

- 修改后的 `deploy/docker-compose.yml`、`deploy/.env.example`、三个通用脚本和 `deploy/README.md`。

1. 请验证 DataHub 1.7.0 能否使用 KRaft 模式的 Kafka 3.9 以及元数据服务内置的模式注册功能。如果不能，请停止工作并且提出备选方案，由架构师决定。
2. 请说明 DataHub 1.7.0 的官方编排文件中实际包含哪些容器，以及本次裁剪去掉和保留了哪些容器。
3. 请说明 DataHub 在 MySQL 中使用的数据库名称与账号是否与设计文档第 7.1 节一致。
4. 第 7 条验收命令的输出是里程碑 M0 的关键数据，请完整提供。
