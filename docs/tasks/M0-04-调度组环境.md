# M0-04 调度组环境

## 目标

能够用一条命令启动 `scheduler` 分组，DolphinScheduler 的元数据存放在 MySQL 中，并且调度节点能够向 YARN 提交 Spark 作业。

## 前置任务

M0-02。

## 依据的设计文档

- `docs/01-环境与部署设计.md` 第 3 节至第 6 节中与 `scheduler` 分组有关的内容，以及第 7.6 节。

## 实现范围

1. 新增 `deploy/images/dolphinscheduler/`，在 DolphinScheduler 3.4.2 的官方单机镜像之上加入 MySQL 驱动、Hadoop 客户端和 Spark 客户端，以及它们的配置文件。
2. 在 `deploy/docker-compose.yml` 中增加 `scheduler` 分组的服务，并且在 `deploy/.env.example` 中增加所需的变量。
3. 配置 DolphinScheduler 使用 MySQL 中的 `dolphinscheduler` 数据库，首次启动时初始化元数据表，重复启动时不得重复初始化。
4. 扩展 `dp-up.sh`、`dp-down.sh` 和 `dp-health.sh`，使它们支持 `scheduler` 分组。
5. 更新 `deploy/README.md`，说明登录地址与修改默认管理员密码的方法。

## 明确不做的范围

- 不创建任何项目、工作流和数据源，这些内容属于里程碑 M2。
- 不部署集群模式的 DolphinScheduler。
- 不配置告警渠道。

## 验收命令

以下命令的执行环境均为阿里云服务器，工作目录为 `/opt/dataplatform`，前置条件是 `core` 分组已经启动。

| 序号 | 命令 | 期望输出 |
| --- | --- | --- |
| 1 | `bash deploy/scripts/dp-up.sh scheduler` | 服务启动，退出码为 0。 |
| 2 | `bash deploy/scripts/dp-health.sh scheduler` | 检查通过，退出码为 0。 |
| 3 | `docker compose -f deploy/docker-compose.yml exec dolphinscheduler bash -lc "hdfs dfs -ls / && spark-submit --version"` | 两条命令都成功执行。 |
| 4 | 在 `dolphinscheduler` 容器内，以 cluster 模式向 YARN 提交 Spark 自带的 SparkPi 示例作业，完整命令写在合并请求中 | 作业的最终状态为 SUCCEEDED。 |
| 5 | `docker compose -f deploy/docker-compose.yml exec mysql mysql -udolphinscheduler -p<密码> -e "select count(*) from information_schema.tables where table_schema='dolphinscheduler'"` | 表的数量大于 0，证明元数据存放在 MySQL 中。 |
| 6 | 重启 `scheduler` 分组之后再次执行第 2 条命令 | 检查仍然通过。 |

## 交付物

- `deploy/images/dolphinscheduler/`，修改后的 `deploy/docker-compose.yml`、`deploy/.env.example`、三个通用脚本和 `deploy/README.md`。

1. 请说明 DolphinScheduler 3.4.2 官方镜像内部的 JDK 版本。如果该版本高于 8，请验证 Hadoop 3.3.6 的客户端与 `spark-submit` 能否在该 JDK 上正常工作。如果不能，请停止工作并且提出备选方案，由架构师决定。
2. 请确认 DolphinScheduler 3.4.2 的单机模式是否支持把元数据库改为 MySQL，并且说明所需的配置项。
